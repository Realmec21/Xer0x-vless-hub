# Xer0x-vless-hub

Автоматический сборник публичных VLESS-профилей: сканирует открытые источники, проверяет каждый профиль на работоспособность, определяет страну сервера, переименовывает профиль в формате `🇳🇱 Xer0x-01` и публикует два файла-подписки.

- `subscriptions/whitelist.txt` — профили, которые должны работать в режиме белого списка (стандартный TLS, публичный сертификат, нормальная задержка)
- `subscriptions/blacklist.txt` — все остальные рабочие профили
- `subscriptions/report.json` — полный отчёт (страны, задержки, TLS, статистика)

Обновление: раз в сутки через GitHub Actions (cron `23 3 * * *`), вручную — `workflow_dispatch` вкладка Actions → Update subscriptions → Run workflow.

## Подписка в клиенте

Ссылки (после создания репозитория):

```
https://raw.githubusercontent.com/Realmec21/Xer0x-vless-hub/main/subscriptions/whitelist.txt
https://raw.githubusercontent.com/Realmec21/Xer0x-vless-hub/main/subscriptions/blacklist.txt
```

В клиенте (v2rayN / v2rayNG / NekoBox / Hiddify / Streisand): **Подписки → Добавить подписку** → вставить ссылку → Обновить.

## Как это работает

1. **Сбор** — качает списки из `config.json → sources` (открытые агрегаторы), вытаскивает `vless://` URI (в т.ч. из base64-подписок), удаляет дубликаты: сначала полные (одинаковые параметры в любом порядке), затем по эндпоинту `uuid@host:port` (`dedupeByEndpoint: true`).
2. **Проверка** — для каждого профиля поднимается изолированный xray-core (HTTP-прокси на локальном порту), через него выполняется реальный запрос к `https://www.cloudflare.com/cdn-cgi/trace`. Профиль жив, если пришёл ответ и известен egress IP. Измеряется задержка.
3. **Гео** — IP сервера резолвится и определяется по ip-api.com; в имя профиля подставляется флаг страны сервера (если geo не удался — флаг из страны egress, иначе 🌐).
4. **Классификация (whitelist/blacklist)** — считаются признаки «пройдёт ли профиль через белый список» (см. ниже).
5. **Сборка** — профили сортируются по задержке, получают имя `ФЛАГ Xer0x-NN`, пишутся два файла подписки.

### Критерии белого списка (`config.json → whitelist`)

| Критерий | Смысл | По умолчанию |
|---|---|---|
| `requirePublicTls` | Прямое TLS-соединение к серверу: цепочка сертификатов доверена и имя совпадает (публичный сертификат — признак домена/CDN, который режут реже всего) | `true` |
| `requireDomain` | Сервер должен быть доменом, а не IP | `false` |
| `requireCdn` | DNS CNAME указывает на CDN (Cloudflare/Fastly/Akamai и т.п.) | `false` |
| `maxLatencyMs` | Порог задержки | `800` |

Конфиг для «жёсткого» белого списка: `requireDomain: true, requireCdn: true, maxLatencyMs: 500`.

## Запуск локально

Нужен Node.js 18+ (xray-core скачивается автоматически).

```bash
node src/index.js            # полный прогон
node src/index.js --limit 30 # быстрый тест на 30 профилях
```

Структура:

```
config.json            — источники, ник, критерии, таймауты
src/index.js           — оркестратор
src/collect.js         — сбор и дедупликация
src/validate.js        — проверка через xray-core + curl
src/geo.js             — DNS + ip-api + флаги
src/classify.js        — whitelist/blacklist
src/build.js           — переименование и запись подписок
.github/workflows/     — автообновление раз в сутки
```

## Правила репозитория

- Публикуются только те профили, которые прошли реальную проверку подключения.
- Каждый прогон перезаписывает оба файла целиком: мёртвые профили автоматически выпадают в следующий цикл.
- `report.json` содержит все результаты для отладки.

## Дисклеймер

- Профили собираются из публично опубликованных списков; серверы принадлежат третьим лицам. **Трафик через чужой сервер виден его владельцу** — не отправляйте через такие профили пароли, платежи и другую чувствительную данные.
- Работоспособность и легальность использования в вашей юрисдикции не гарантируются; автор не несёт ответственности за содержимое сторонних серверов.
- Проверка занимает время и ресурсы CI; при пустом результате новый коммит не создаётся, остаются прошлые файлы.
